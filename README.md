<!-- --- Abstract  -->


LTCook connects Pi agents to Paseo's existing chat interface. AppRC owns
configuration and installation management; a small TypeScript runtime owns
coordination in SQLite. Choose the full default team or a two-agent team
containing only Main and Adjutant.

This is a new application named `ltcook`, not an upgrade or compatibility layer
for `lcook`. Its setup and cleanup must leave existing `lcook` installations,
settings, and data alone. LTCook performs its own versioned coordination-database
migrations while preserving LTCook Session identities and native bindings; it does
not import or migrate data from an independent `lcook` installation.


#### Main dependencies:
- **[Pi](https://github.com/badlogic/pi-mono)**: Native agent tools and conversations.
- **[Paseo](https://github.com/getpaseo/paseo)**: Chat, agent connectivity and the team-status panel.
- **[`apprc`]**: Typed settings, workspace overrides, secret env files and application lifecycle.
- **[libsql](https://github.com/tursodatabase/libsql-js)**: One embedded SQLite driver for Bun development and Node deployment.
- **SearXNG, pi-web-access and Crawl4AI**: Search and page retrieval; reasoning and citations stay with Pi.

The scaffold was generated by [Buildben](https://github.com/HisQu/buildben).
Third-party packages retain their own licences.

# Installation

The installer uses Python 3.12 or newer through `uv`. If `uv` is not available,
it installs the official user-scoped `uv` executable and lets `uv` provision a
compatible Python; no system Python or administrator access is required.

Application setup also prepares Node and the selected web-service prerequisites.
Installing a missing Podman may require the host's normal elevation or package
manager. Merely entering this repository or inspecting status must not install
software or start services.

<br>

## Install a release

> [!NOTE]
> No LTCook release has been published yet. Use the checkout workflow below.
> Release downloads in this section apply only after an actual release exists.

The generated release-mode native entry can run by itself. It acquires and
verifies the matching source and release manifest; adjacent manifest and
`main-installer.py` files are not required. Downloading the complete release
asset set is an optional workflow when you want to inspect or retain those
assets locally.

```shell
gh release download vX.Y.Z --repo markur4/ltcook
./app-install.sh
```

On Windows, run the downloaded `app-install.cmd` instead:

```powershell
gh release download vX.Y.Z --repo markur4/ltcook
.\app-install.cmd
```

The default source selection installs the pinned source archive. `--version
X.Y.Z` selects a specific published release, and `--main` resolves the
repository's current `main` to one immutable commit for that invocation. These
choices cannot be combined. `--github-client gh` selects authenticated GitHub
CLI downloads; public downloads do not inherit GitHub CLI credentials. Private
VCS dependencies separately require Git credentials. Installing missing native
prerequisites on Windows can require administrator privileges.

For a source checkout, first generate its local AppRC artifacts with
`just make-artifacts`, then use `./app-install.sh` or `.\app-install.cmd`.
`just check-artifacts` verifies tracked output without rewriting it. A missing
checkout payload reports the generation command; it never fetches a replacement
from a remote repository.
These authoring recipes use uv's locked project environment; an activated virtual
environment or direnv is not required.

The installer offers native or single-root resource placement when the
application declares resource capabilities. Use `--layout native` for native
locations or `--layout single-root --root ABSOLUTE_PATH` for a single root.
Reinstallation keeps the saved absolute placement unless an explicit layout
override is supplied. LTCook declares config, appdata, cache and state paths.

Configuration setup is optional and does not block installation management.

<br>

## Install from a checkout

Clone the repository, synchronize its locked authoring environment, and
generate local AppRC artifacts before running the checkout installer:

```shell
git clone https://github.com/markur4/LTCook.git
cd LTCook
just sync
just make-artifacts
```

On Linux and macOS, run:

```shell
./app-install.sh --layout native
ltcook launch runtime
```

On Windows, run:

```powershell
.\app-install.cmd --layout native
ltcook launch runtime
```

The checkout install is editable and uses the actual project files, including
uncommitted changes. It does not alter the repository's saved source revision.
Use `just check-artifacts` to check generated outputs without rewriting them.

<br>

## Uninstall

Run `./app-uninstall.sh` on Linux or macOS, or `.\app-uninstall.cmd` on Windows.
The default removes the managed program and retains declared resources and
installation recovery support. Complete removal requires an explicit request:

```shell
./app-uninstall.sh --complete --category config --category appdata --yes
```

Use the same options with `app-uninstall.cmd` on Windows. Only select resource
categories that the application declared; unknown files and external data are
not inferred as cleanup targets. The saved uninstall code invokes any
repository-owned cleanup before removing the installed program. Inspection and
recovery use `ltcook installation show`, `ltcook installation
doctor`, and `ltcook installation repair`.

The saved controller is stored under the fixed native `installation/` address,
separate from application data. Repeated commands do not redirect it when the
shell's `HOME`, XDG variables, or `LOCALAPPDATA` change.

# Usage

The installed command and AppRC management remain available before business
setup. Run these commands from the installed application environment:

```shell
ltcook version
ltcook diagnose --json
ltcook installation show
ltcook config show --json
ltcook launch runtime
```

This starts Paseo's UI without opening a project or creating agents. Select a
project directory in Paseo and use **Start session** in the LTCook panel, or run
`ltcook launch runtime --workspace ROOT` to open it from the terminal.
Registration and AppRC workspace markers are optional; existing project settings
are used when present. Model selections are needed when starting agents, not
merely opening the UI.

Application resources use the paths declared by `APP_RC`. Config, appdata,
cache, and state are independent capabilities; disabled paths stay absent and
installation management does not enable them. The `installation/` authority is
separate from application data. See the
[filesystem capabilities](docs/Explanations.md#filesystem-capabilities) and
[installation placement reference](docs/References.md#installation-placement).

## Authenticate with Pi

Use Pi's native provider login through LTCook:

```shell
ltcook auth login openai
ltcook auth check --provider openai --json --no-refresh
```

For OpenAI, account sign-in and an API key are different authentication methods.
Use `ltcook auth login openai --api-key` for an API key instead. Pi stores
credentials in the shared user home, normally `~/.pi/agent/auth.json`; project
settings and conversations remain separate. Existing credentials in that home
are reused without copying them into projects. See the
[authentication guide](docs/How-To-User-Guides.md#authenticate-with-pi) for
logout, headless login, and a custom `runtime.pi_auth_dir`.

LTCook still selects team models through `runtime.smart_model`,
`runtime.smol_model`, and `runtime.plan_model` in `ltcook config edit`.

<br>


## Choose a team

Set `LTCOOK_TEAM` through AppRC's configuration editor or a deliberate shell
override. `default` has six persistent roles plus explicitly requested temporary
specialists. `default-minimal` has exactly Main and Adjutant; Main does the work
of absent specialists and does not claim an independent review.

```shell
LTCOOK_TEAM=default-minimal ltcook launch runtime --workspace .
```

Opening a project without `LTCOOK_SESSION` starts a fresh chat Session. Starting
the server without a project creates no Session. To resume a chat, explicitly set
`LTCOOK_SESSION` to its existing identifier with the same workspace and team.
Multiple Sessions in one workspace share a logical persistent TeamInstance but
keep separate native conversations and agent bindings. See
[domain terminology](docs/Explanations.md#domain-terminology).

The selected team stays fixed for a running session. Coordination uses the
selected package's public API, not imports of the default team's internals.


<br>

## Develop with Bun

Bun is the development runtime. The grouped Just module exposes
`just runtime sync`, `dev`, `check`, `test` and `build`; there is no separate
frontend or chat server. Start with the
[development environment](docs/Development.md#maintainer-environment) and
[normal checks](CONTRIBUTING.md#run-checks).

Routine behavior checks do not call models or start application agents.
Live service, browser and installed-application checks are separate from that
quick loop and require their stated prerequisites.
